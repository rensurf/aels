# 主要設計判断

面接準備用 — このプロジェクトにおける主要な技術選定の「なぜ」をまとめたもの。

---

## なぜリレーショナルDBではなくグラフDBを使ったのか

フレーズには関係性がある。一つのフレーズは複数のトピックに属し、関連するフレーズとつながり、ユーザーの学習履歴と結びつく。「自分が苦手なものに関連するフレーズを見つける」というクエリはグラフ走査が自然に表現できる。CosmosDB の Gremlin API はインフラを自前で管理せずにスケーラブルなグラフストレージを提供してくれる。

## なぜ復習スケジューリングに SM-2 アルゴリズムを使ったのか

SM-2 は Anki が採用しているアルゴリズム。フレーズごとに `ease_factor`（難易度）・`interval`（次回復習までの日数）・`repetitions`（正解回数）の3つを追跡し、回答の正確さに応じて次回の復習タイミングを調整する。正解すれば間隔が指数的に延び、不正解ならリセットされる。これにより、本当に必要な場所に復習時間を集中できる。

## なぜ直接 API 呼び出しではなく Agent Framework を使ったのか

エージェントパターンは関心を明確に分離できる。`Client` が LLM API を呼び出し、`Agent` がインストラクションとツールを定義し、`Session` が会話履歴を保持する。GPT-4o を別のモデルに切り替えるには `Client` を変えるだけでいい。ツール関数は通常の Python 関数であり、特別なデコレーターは不要。型アノテーションと docstring がそのままスキーマになる。

## なぜサーバーではなく AWS Lambda を使ったのか

Telegram ボットのトラフィックはバースト性が高く、予測しにくい。Lambda はアイドル時にゼロにスケールする（コスト: $0）。29秒のタイムアウトは Telegram の30秒 webhook 制限に合わせた設定。

## なぜ AWS と Azure を分けたのか

コンピューティングとセッション管理（DynamoDB）は AWS Lambda（リージョン: ap-southeast-2）を使用。グラフストレージは Azure CosmosDB — Gremlin API は CosmosDB 固有であり AWS に同等のサービスがない。Terraform が一つの `apply` で両プロバイダーを管理する。
